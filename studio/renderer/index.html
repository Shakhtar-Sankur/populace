About Populace

      
What it is for, how to use it, and what it will never do.

    


    

      

        
        

          
 A Gigzen product

          
Your app, used by people who don’t exist.

        

      


      

        Software breaks in front of people, not in front of tests. It breaks when two
        strangers touch the same row at the same second, when a policy quietly refuses a
        write, when a token expires halfway through an afternoon. None of that shows up
        when one developer clicks through one screen.
      

      

        So Populace brings a population to life inside your application. Each person
        has a name, a city, a language and a job, and they use your real API the way people
        do — signing up, moving, posting, arguing, going quiet, coming back. Then they
        delete themselves and hand you a report that says what broke, why, and what to
        do about it. Nothing it cannot prove goes in that report.
      

    


    

      
How to use it
five steps, about ten minutes

      
    
        
  1. 
          Point it at a test environment.
          A populace.config.mjs names your app, your adapter and the URL to run
          against. Every host you list under neverRunAgainst is refused before a
          single account is made.
        
    2. 
        
  2. 
          Write an adapter, or start from one.
          Thirteen methods — sign up, sign in, post, read the feed, like, comment,
          message, report a location, join a group, delete the account. Each one maps onto
          whatever your app actually calls those things. populace init --from-openapi
          drafts it from an API description.
        
    3. 
        
  3. 
          Choose the population.
          How many people, for how long, in which cities, and how hard they use it.
          Engagement multiplies how often each person acts — the same hundred people at
          three times the appetite is a very different load.
        
    4. 
        
  4. 
          Watch it happen.
          The Live screen shows every person, every method, and the throughput as it moves.
          The map is where they are; scroll to zoom into a city.
        
    5. 
        
  5. 
          Read the verdict, then ask why.
          Report gives the numbers per method. Explain turns a failure into a cause and a
          fix — a permission policy, a missing column, a token that expired —
          rather than an error string to search for.
        
    6. 
      

    


    

      

        
What it refuses to do

        
    
          
  • Run against a host in neverRunAgainst — production is denied before startup.
    • 
          
  • Leave accounts behind. Every person it creates, it deletes.
    • 
          
  • Call a run clean when it could not make every call.
    • 
          
  • Send anything about your app, your credentials or your runs anywhere.

Privacy

      
What this software does with your data. Every line of it was checked against the code.

    


    

      
Populace collects nothing about you. There is no account, no telemetry,
        no analytics, no crash reporting and no identifier of any kind. Nobody at Gigzen can tell that
        you ran it, what you ran it against, or what it found.

    


    

      
What stays on this machine

      
    
        
  • Your configuration and credentials. The URL, keys and environment variables a run
          needs are read on this machine and used only to call the target you named. They are never
          transmitted anywhere else and never written into a report.
    • 
        
  • Your reports. Written beside your config, or to
          Documents\Populace\ when that folder cannot be written to. They stay there
          until you delete them.
    • 
        
  • Everything the simulated people do. That traffic goes from this machine to the
          target in your configuration and nowhere else.
    • 
      

    


    

      
What leaves this machine
three requests, all optional


      

        
1. The version check

        
An anonymous GET to api.github.com when you press
          Check for a newer Studio, and to registry.npmjs.org when the engine
          checks itself. No identifier is sent, and the engine's check is off entirely when
          POPULACE_NO_UPDATE_CHECK=1 or CI is set.

      


      

        
2. Model explanations — only if you set a key

        
If, and only if, ANTHROPIC_API_KEY is set, failures that no built-in rule
          could name are sent to api.anthropic.com. Exactly four fields go with each
          one:

        
    
          
  • method — the contract method name, such as like
    • 
          
  • error — the error message, truncated to 500 characters
    • 
          
  • occurrences — how many times it happened
    • 
          
  • p50ms and p95ms — two latency numbers
    • 
        

        
Read this one carefully. The error message is your application’s
          own text, so it can contain a table or column name — for example
          new row violates row-level security policy "post_likes_insert". No URL, no
          credential, no persona and nothing about your configuration is included. If that trade is
          not one you want, leave the key unset: the rules still run, and most runs never need the
          model at all.

      


      

        
3. Links you click

        
Opening a link from this window hands it to your browser. Nothing is sent with it.

      

    


    

      
The accounts it creates

      
A run signs up people in your application, on the target you named.
        Every one of them is deleted when the run ends, and the report states how many were removed
        of how many were made. What your application keeps of what a deleted account wrote is your
        application’s behaviour, not something Populace changes.

    


    

      

        
Children

        
This is a developer tool. It is not directed at children and collects
          nothing from anyone, including them.
